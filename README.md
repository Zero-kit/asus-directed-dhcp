# 华硕定向 DHCP · AXDHCP

在同网段的 AP / 无线中继环境中，为选中的下游 Wi-Fi 提供独立 DHCP 地址池，客户端仍使用上游路由器作为网关。

适用于带 KoolShare / KoolCenter 软件中心的 hnd Asuswrt-Merlin 固件。当前离线安装包版本为 **0.5.6**，插件名称为 `axdhcp`。建议 GitHub 仓库名：`asus-directed-dhcp`。

## 功能

- 识别网络桥、无线频段、SSID 和接口角色，选择上游回程及一个或多个下游 Wi-Fi。
- 配置地址池、子网掩码、网关、DNS 和租约时长。
- 手动启动、停止恢复，可选开机自动运行。
- 查看租约、过滤规则计数、日志及只读诊断报告。
- 监控接口、规则和服务进程，异常时停止插件 DHCP 并尝试清理自有规则。

所选下游 Wi-Fi 共用一套地址池。插件使用独立的 DHCP-only dnsmasq，通过 ebtables 对所选接口过滤 DHCP 报文；不创建新网段或 NAT，也不替代上游网关。

## 适用范围

要求 Broadcom `wl`、legacy `ebtables`、支持 DHCP 的 `dnsmasq`，以及兼容的软件中心 API。安装按工具和目录能力检查，不固定软件中心版本号或设备型号。

网络应处于同网段桥接的 AP / 中继模式，要求 `ip_forward=0`。系统 dnsmasq 必须明确排除所选桥的 DHCP 服务，其包含配置也会在启动前检查。下游无线接口须能识别为 AP，并与回程同属所选桥。

已在 **RT-AX86U** 上由用户确认安装、手动运行、客户端租约记录和修复后的开机自启。其他型号的无线驱动和硬件转发路径可能不同，仍需实机核对。完整的广播/单播过滤、续租、漫游及长期稳定性尚未完成验收。

接口识别依据见 [接口选择说明](docs/interfaces.md)。

## 安装与配置

1. 获取 `axdhcp-0.5.6-interfaces.tar.gz`，在软件中心选择离线安装。
2. 打开“华硕定向 DHCP”，核对网络桥、上游回程和下游 Wi-Fi。
3. 设置地址池、网关、DNS 和租约时长，确认地址池无占用且 DNS 可用。
4. 点击“启动”，页面会先保存当前配置，再启动服务。
5. 需要重启后运行时，勾选“开机自动运行”并点击“保存配置”。

地址池须与上游动态池、静态地址、保留地址和绑定地址错开，并与桥地址、上游网关处于同一子网。填写实际可用的 DNS；上游网关不一定提供 DNS 服务。

“保存配置”只写配置。“停止并恢复”停止当前服务并撤销插件规则，不改变已保存的开机设置。若希望重启后也保持停止，取消“开机自动运行”并保存。

开机任务在网络就绪后立即启动，通常不需要等满三分钟；超时或失败会记录日志。开机入口由软件中心的 services-start 调用，无需 WAN 连接。

## 升级与卸载

升级会停止现有服务、保留配置，并关闭开机自动运行及后端启用标记。升级后核对配置，重新点击启动，并按需勾选开机运行、保存。

安装成功后清理临时安装恢复目录。安装失败时尝试恢复原文件；恢复不完整时保留相关文件供排查。

卸载先停止服务，再移除软件中心入口；后端和配置保留在 `/koolshare/axdhcp.retired.*` 供恢复。停止失败时保留安装。

详细操作见 [运行说明](docs/integration-package.md) 和 [恢复手册](docs/recovery.md)。

## 常见问题

**为什么第一个客户端没有拿到地址池起点？**

dnsmasq 默认不按地址从小到大依次分配，会根据客户端标识、已有租约和请求地址选择池内地址。

**租约时间为什么有时显示时长，有时显示日期？**

部分固件的 dnsmasq 使用 no-RTC 构建，租约文件记录时长；其他构建记录到期时间戳。页面兼容两种格式。只提供时长时无法据此算出准确剩余时间。

**切换 Wi-Fi 后为什么还保留原地址？**

同网段漫游可能沿用旧租约。验证地址池时，需要重新申请 DHCP，并核对租约与服务端来源。

**这个插件能隔离设备吗？**

设备仍在同一网段，可以互相访问。静态 IP 不受地址池限制，插件不改变现有 IPv6 配置。

**开机自动运行没有生效怎么办？**

确认开机选项已保存，尤其是刚升级之后。展开页面底部“诊断与使用说明”，查看日志并复制诊断报告。日志可区分开机入口调用、设置关闭、网络等待和启动失败；路由器时钟未校准时，日志日期可能不正确。

分享报告前请遮蔽 SSID、MAC、主机名及其他个人网络信息。租约记录只能证明发生过分配，不能单独证明上下游 DHCP 过滤完整。

## 开发与打包

开发机需要 Python 3、Node.js、`jq` 和常规 shell 工具；路由器运行不依赖 Python 或 Node.js。

```sh
# 本地回归与静态检查
python3 -m unittest discover -s tests -v
sh tools/check.sh

# 构建软件中心离线安装包，输出至 dist/
sh tools/build-router.sh

# 预览页面
node tools/preview.mjs
```

预览地址为 `http://127.0.0.1:8765/`，未连接路由器，保存只写浏览器本地配置。模拟测试不会验证实际无线报文路径。真实 dnsmasq 配置解析测试可通过 `AXDHCP_TEST_DNSMASQ` 指定开发机上的 dnsmasq 可执行文件；未配置时跳过该项。BusyBox 和 ShellCheck 缺失时，静态检查会明确报告跳过。

软件中心包版本由 `tools/build-router.sh` 定义。根目录 `VERSION` 及 `tools/build.sh` 对应早期独立审查包；该包不能通过软件中心离线安装。

| 目录 | 内容 |
| --- | --- |
| `backend/` | 配置校验、接口识别、DHCP 生命周期与只读检查 |
| `adapters/koolshare/` | 软件中心安装、卸载、API、开机入口及页面外框 |
| `web/` | 配置页面和状态展示 |
| `config/` | 配置示例；实际配置需按设备修改 |
| `tests/` | 后端、安装、API 和页面回归 |
| `tools/` | 检查、打包、环境采集及预览工具 |
| `docs/` | 运行、恢复、设计及历史验证记录 |

历史开发文档可能描述早期版本，请以本文和当前 [运行说明](docs/integration-package.md) 为准。验证记录见 [本地验证记录](docs/validation.md)，报文路径讨论见 [设计审查](docs/design-review.md)。
