# 0.3.0 限时过滤现场测试

0.4.1 的普通“启动”为长期运行，可选开机自动运行，客户端验收可后续进行，操作说明见 `integration-package.md`。以下为限时测试工具的流程，不是普通启动的前置要求。

限时 DHCP 测试需先完成实际路径核验，再保存 enabled=1、地址池无占用确认和 DNS 确认。过滤事务需先停止，不能直接切换为 DHCP。网页路径核验项每次刷新默认不选，不持久化为硬件验证通过。点击“试运行华硕发地址”并明确确认，后端执行 test 加网络授权及路径确认参数；默认 300 秒，允许 30–300 秒。限时测试不改变开机设置，开机启动使用长期运行模式。

启动后核对 mode=dhcp、service=started、rules=intact、remaining_seconds。选中频段的客户端重新申请 DHCP，应获取保存的池地址、网关和 DNS，server identifier 应为桥实际地址。上游客户端重新申请应仍由上游服务分配，不能看到插件应答；华硕管理租约不能由自身分配。出现泄漏或来源不一致立即“停止并恢复”。到期自动先停 DHCP 再撤销规则，已发出的客户端租约仍需客户端重新申请恢复。状态 hardware_verified=0 表示尚未完成真实验收，不是服务运行开关。

本次仍不能宣称成品：启动入口已实现，真实 dnsmasq / 博通报文隔离需现场确认；若原始套接字路径绕过过滤，不能用勾选确认项绕过证据缺失。

此版通过已验证能读写的软件中心 API 提供 filters 和 stop 动作。仅允许已保存配置下的临时过滤，默认关闭 DHCP、无开机运行。安装与升级本身不启动测试。

现场先准备上游客户端、选中频段的下游客户端与独立管理/恢复渠道。保存配置，可先将测试窗口设为 60 秒；保存后点击限时过滤测试并确认网络变更。过滤期间下游 DHCP 被阻止，可能无法续租，测试没有第二 DHCP 提供新地址。界面应显示 mode=filters、rules=intact、remaining_seconds；DHCP 已停止。查看规则计数和日志，收集上下游 DHCP 报文证据，不能把计数增加当作实际过滤通过。

点击停止并恢复，应显示 service=stopped，无 generation。再执行只读检查核对父链不存在 AXDI/AXDF/AXDO 跳转。再次启动并等待到期，确认相同恢复行为。若出现错误或恢复失败，保留日志与状态，不要再次启动。原始套接字 INPUT/OUTPUT 旁路尚不能用过滤测试排除，DHCP 按钮继续关闭。

包含目录门禁仅允许 /jffs/configs/dnsmasq.d 存在、非符号链接且完全为空；非空/其他路径均拒绝。不会删除系统文件来满足检查。网络接口、网关和设备仍按已收集环境限定，通用展示不代表任意固件可运行。

API 请求走固件已登录会话的同源接口，不开放独立 Web 服务。filters 必须携带明确确认参数；该参数是操作意图，不是安全凭证。固件自身认证/CSRF 防护与报文路径的完整验收仍须记录，硬件状态不自动提升。
